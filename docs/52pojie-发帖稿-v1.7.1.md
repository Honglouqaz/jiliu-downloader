一、这是个什么东西

一句话：把「下什么东西」和「怎么下」分开处理。

浏览器自带的下载器只会做一件事——从第一个字节顺序拉到最后一个字节。
于是这些情况它都处理不好：

· 2GB 的 ISO        单线程，断了从零开始
· 40KB 的图标       也走完整下载流程
· m3u8 流清单       拉下来一堆碎片，拼不起来
· 没后缀的 CDN 链接  存成 download.bin
· zip 伪装成图片     存下来说打不开
· 一集一集的合集     只能手动点
· magnet: / .torrent 完全不认

汲流的做法是先认清「这是什么」，再决定用哪种方式搬。

—————————————————————————

二、主要功能

1. 下载核心

· 多线程分片：默认 8 线程，按文件大小自适应，小文件不折腾
· 断点续传：分片级续传，不是整文件重来
· 完整性校验：下完算 SHA256，安装包/压缩包坏了当场能看出来
· 限速与并发：总速度上限、同时任务数、单任务连接数都能调
· 队列管理：暂停 / 继续 / 重试 / 删除 / 重新下载，状态全部落盘，关掉软件再开还在

2. 类型识别

· 读文件头魔数判断真实类型，不信后缀
· 后缀缺失自动补，后缀伪装自动推翻（zip 改名成 .jpg 也能认出来）
· 图片、字体这类小文件直接单线程，不占分片名额
· 装完自动按类型归档到子目录（视频 / 音频 / 文档 / 压缩包 / 安装包 / 图片 / 其他）

3. 多引擎，择优使用

内置六种搬运方式，按任务类型自动挑：

· 自研分片引擎  —— 通用 HTTP/HTTPS，主力
· aria2c        —— BT / 磁力 / 多源
· curl / wget   —— 服务器不兼容分片时的退路
· yt-dlp        —— 视频站点解析
· ffmpeg        —— 音视频合流、转封装

引擎缺失不会报错崩掉，会自动降级并在设置页标出「未安装」和获取方式。

4. 视频

· 内置 yt-dlp 引擎，支持其站点清单内的公开视频（具体以 yt-dlp 官方支持列表为准）
· 对部分国内平台做了原生取流（DASH 音视频双流分离下载再合并），不依赖上游解析
· 合集 / 播放列表展开成条目列表，勾选要哪几集，批量入队
· 支持纯音频、纯字幕模式
· m3u8 / mpd 直链直接喂进去，走分片并发下载后合流

5. BT 与特殊链接

· magnet: 与 .torrent 交给 aria2 的 BT 引擎（DHT / PEX / LPD 找源）
· thunder:// 等迅雷链接解壳还原成真实地址，仍走多线程
· 注意：BT 功能需要自行放置 aria2c.exe，本版未随包附带（体积原因）

6. 浏览器接管

· 自带 Chrome / Edge 扩展，接管浏览器下载，按文件类型自动选引擎
· 不想装扩展也可以：内置本地嗅探代理，把系统代理指过去就行
· 接管规则可配：哪些站接管、哪些后缀忽略、哪些走浏览器原生
· 剪贴板监听：复制链接自动弹窗问要不要下

7. 自动化

· 计划任务：定时开始 / 暂停 / 限速（比如白天限速、夜里满速）
· 时段限速：按星期几 + 时间段生效
· 订阅源：定时检查 RSS / 指定页面，有更新自动入队
· 完成后动作：系统通知、打开目录、执行命令、阻止休眠

8. 界面

· 原生桌面窗口（pywebview + Edge WebView2），不是浏览器套壳，没有终端窗口闪一下
· 也可以只用 Web 面板：jiliu.exe serve，然后用浏览器打开
· 系统托盘：关闭窗口最小化到托盘，不退出下载
· 日间 / 夜间两套配色

三、怎么用

方式一：便携版（推荐，不写注册表）

解压到任意目录（U 盘也行）→ 双击 jiliu.exe。
包里有个名为 portable 的空文件，它的存在就是便携开关：配置、任务记录、
下载目录全部落在程序目录下的 data/ 与 downloads/，不往用户目录写任何东西。
整个文件夹拷走就是完整搬家。

方式二：源码运行（需要 Python 3.9+）

python jiliu.py           启动桌面窗口
python jiliu.py serve     只要 Web 面板 + API
python jiliu.py add <url> 直接下一个

方式三：命令行

jiliu.exe add "https://example.com/file.iso" -d D:\Downloads
jiliu.exe status
jiliu.exe pause <id>

四、两个刻意的设计，说明一下

1. 为什么要先「认类型」再下载

因为下错方式比下慢更烦人。一个 40KB 的图标拿 8 线程去切，握手开销比传输还大；
一个 m3u8 用普通分片引擎拉，下完是一堆拼不起来的 ts。
所以流程是：先探（HEAD + 读头部若干字节）→ 定类型 → 选引擎 → 再搬。

2. 为什么有两套「接管」

扩展接管是在浏览器层面把请求拦下来，最准，但要装扩展；
本地嗅探代理是在网络层面截，不用装东西，但要改系统代理。
两条路都给，是因为单位电脑装不了扩展的情况很常见。
