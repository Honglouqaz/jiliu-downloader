快速开始

最短路径：装好 → 开面板 → 装插件。三步。

装汲流

双击 jiliu-setup-1.0.0.exe 安装，或者解压便携版后双击 jiliu.exe。装完桌面会有快捷方式。

开汲流

双击 汲流。出来的就是一个正常的窗口 —— 有标题栏、有任务栏图标，没有终端黑框、也不开浏览器。

想要老的浏览器面板？用 jiliu.exe serve，然后开 http://127.0.0.1:8788。

装浏览器插件

地址栏进 chrome://extensions → 右上角打开开发者模式 → 点加载已解压的扩展程序 → 选 extension 文件夹。

装完点插件图标，确认 API 地址是 http://127.0.0.1:8788。

这就完了

之后浏览器里点任何下载链接，汲流会自己判断值不值得接管。 值得就抢过来用多线程下、下完校验；不值得就放行让浏览器自己下。 你不会被拦，也不会被烦到。

三种装法

看场合挑一个。装错形态也没关系 —— 三者共用同一份配置文件逻辑。

一、安装版 jiliu-setup-1.0.0.exe

双击即装，装到 %LOCALAPPDATA%\Programs\Jiliu\， 建开始菜单和桌面快捷方式，写卸载项（控制面板里能正常卸干净）。

参数作用
（无参数）常规安装到默认目录
--target "D:\Tools\Jiliu"装到指定目录
--autostart开机自启（登录后静默起服务）
--no-shortcuts不建任何快捷方式
--quiet静默安装，不弹任何提示
--dry-run只打印将要做什么，不真动磁盘 —— 想先看看它会干啥就用这个
--uninstall卸载

二、便携版 jiliu-portable-1.0.0.zip

解压到任意位置（U 盘也行），双击 jiliu.exe。

portable 这个文件是开关

包里有个叫 portable 的空文件。它的存在本身就是便携模式： 配置、任务记录、下载目录全部落在程序目录下的 data/ 与 downloads/， 不往 %USERPROFILE% 写一个字节。整个文件夹拷走 = 完整搬家。

想改用用户目录（~/.jiliu）？删掉这个文件就行。

三、源码运行

需要 Python 3.9+。适合想改代码或跑测试的场合。

# 双击即开（等价于 gui）：桌面窗口
python jiliu.py

# 只要 Web 面板 + API，不弹窗口
python jiliu.py serve

# 直接下一个（不开服务）
python jiliu.py add https://example.com/big.iso

# 跑全部测试，516 项
python tests/run_all.py

桌面窗口

双击出来的是一个真正的应用窗口，不是「后台起服务 + 开浏览器」。

以前是起了个后台服务，再让系统浏览器打开面板。现在双击 jiliu.exe 出来的是一个原生窗口：有标题栏、能最小化最大化、关掉就退出， 没有终端窗口闪一下。界面还是同一套 HTML，只是换了个原生壳装着 （pywebview + Edge WebView2）。

命令行为
jiliu.exe开桌面窗口（推荐，双击就是这个）
jiliu.exe gui同上，显式写法
jiliu.exe gui --window browser用系统浏览器打开
jiliu.exe serve只起服务，不弹窗口（给插件/远程用）

设置 → 界面 里有三种模式：自动（能开窗口就开，不行退回浏览器）、 原生窗口（始终用窗口）、浏览器。

窗口开不起来会怎样

不会静默退出。GUI 起不来时会恢复控制台并把错误打出来， 你一眼能看到是缺 WebView2 运行时还是别的。也可以直接用 --window browser 绕过。

端口被占了？

不会报错退出。已经开着一个汲流时，新窗口会自动往后顺延端口。

分类归档

选定下载目录后，汲流会在它下面按类型建子文件夹自动归位 —— 不让几百个文件全堆在一个目录里。

<下载目录>/
├── 视频/          mp4 mkv flv rmvb ts …
├── 音频/          mp3 flac wav m4a …
├── 软件/          exe msi dmg apk …
├── 压缩包/        zip rar 7z tar.gz …
├── 文档/          pdf docx xlsx epub …
├── 光盘镜像/      iso img …
├── 图片/          jpg png webp gif …
├── 字体/          ttf otf woff2 …
├── 数据集/        safetensors ckpt …
├── BT/            磁力 / 种子
├── 网盘/          网盘直链
└── （认不出类型的直接放这里）

三个刻意的决定

决定为什么
「其他文件」不建子目录 认不出来的东西再塞进一个「其他」文件夹，只是把杂物换个地方堆， 下次还是找不到。不如让它在根目录显眼。
你显式指定目录时不归档 手动选目录 = 明确意图，再自作主张套一层是添乱。 想让显式目录也归档，设置里开「显式目录也归档」。
只接受单个路径片段 配置里写 ../../Windows 必须被挡掉 —— 这类项是本地接口能写进来的，路径穿越是实打实的风险。

子目录名在 设置 → 归档 里改，也可以把某一类设成空（那一类就不归档）。 B站合集这类「本质还是视频」的分类会归到 视频/，不再单开一层。

# 看当前布局与示例树
python jiliu.py layout

# 预览某个链接会落到哪个文件夹
python jiliu.py layout --url "https://example.com/a.zip"

下载引擎

七个引擎，职责不同，不能互相替代。汲流按链接类型自动择优。

引擎类别定位
自研多线程HTTP 零依赖。按资源类型定制线程数与分片，支持续传/限速/暂停/哈希校验
aria2HTTP + P2P 磁力/种子/ed2k 的唯一选择；也能下普通 HTTP
curlHTTP 兼容性最好。自研引擎下不动的服务端，换它常常就过了
wgetHTTP 对「服务端中途断流」容忍度最高，会自己重连续传
yt-dlp视频 只有它认识几千个站点的页面结构。不是可选功能
ffmpeg合流 音视频分离下载后必须靠它合并；转码、嵌字幕也靠它
N_m3u8DL-REHLS 分片加密、多音轨的流比 ffmpeg 更稳。可选加强项

择优规则

P2P（磁力/种子/ed2k）  → aria2（别无选择）
视频页 / m3u8 / mpd     → yt-dlp
普通 HTTP              → 按「引擎优先级」挑第一个可用的
失败会自动降级

自研引擎偶尔会撞上挑食的服务端，这时候静默换 curl 重来一遍， 比让你对着一个错误码发呆强。降级链可在设置里关掉。

# 看所有引擎与可用状态
python jiliu.py engines

# 改优先级
python jiliu.py config --set engine_order=native,aria2,curl,wget

两个版本：国内版 / 全球版

两个独立的版本，不是同一份程序藏几个按钮。

国内版 cn全球版 global
国内站点✅✅
海外站点（YouTube/TikTok/X…） ❌ 真拦掉 ✅
代理设置界面上不出现✅ 完整
BT / 网盘✅✅

国内版面对的是「只用国内站」的场景 —— 单位电脑、内网、给家人装的机器。 这类环境下把 YouTube、代理这些东西摆在界面上，除了制造困惑没有别的作用 （点了必然失败，还要解释为什么失败）。所以国内版是真的一条都不发： 界面上不出现，逻辑上也拒掉，报错直接说清「本版不含此能力，需要请换全球版」。

判「是不是海外站点」刻意保守

只有明确认识的海外平台才判为海外，白名单之外的域名一律放行。 理由是搞错方向的代价不对称 —— 把国内小众站误判成海外， 会让你正常能下的东西下不了。

# 看当前版本与两种形态的区别
python jiliu.py edition

# 切换
python jiliu.py edition cn
python jiliu.py edition global

代理

下载外网的东西需要代理，但默认不需要你填任何东西。

汲流直接读 Windows 的 Internet 设置（注册表里的系统代理），解析 host:port / http= / socks= 各种写法， 连「哪些地址不走代理」的例外列表也一起读。

模式说明
跟随系统（默认） 读系统代理；系统没配就直连。界面会显示当前读到的是什么
手动 自己填。内置 8 个常见预设，点一下就填好
直连一律不走代理

还有「连不上时自动直连」的兜底开关 —— 代理挂了不至于整个不能用。 代理按链接分流：国内站直连、海外站走代理，两种链接混在一个队列里也没问题。

一个踩过的坑

本机如果同时存在环境变量代理（HTTP_PROXY）和 系统代理，两边可能只有一个是活的。汲流优先用系统代理并验活， 不会闷头走一个已经死掉的环境变量。

# 看当前用的是哪个代理、通不通
python jiliu.py proxy
python jiliu.py proxy --test

网页视频解析（1.9.2）

给一个播放页地址，把里面真正在播的那个流拿下来。不装扩展也能用。

怎么用

  1. 复制播放页地址（不是播放器里的地址；浏览器地址栏那个就是）
  2. 点工具栏「新建任务」→ 粘进去 → 点「解析播放页」
  3. 下面会列出找到的地址，带清晰度。点「下载这条」就进队列

解析出来的请求头（Referer / Origin / Cookie / UA）会跟着任务一起存下来 —— 防盗链 CDN 认的正是这几样，少了就是「地址没错却下不动」。

能认的六种形态

  • 播放器变量：player_aaaa = {..."url":"...m3u8"} —— 苹果CMS / 海洋CMS 系模板，免费影视站的最大族群；多清晰度（4K$... #1080P$...） 与多线路（player_bbbb）都会拆开列出
  • <video> / <source> / data-* 属性：短剧站、老站、自建播放器
  • <iframe> 内嵌播放器：会递归进去（默认 2 层）， 顺带解出 ?url= 参数里编码过的地址
  • 内联脚本：hls.js / dash.js 配置、window.__INITIAL_STATE__， 含 https:////// 这类转义写法
  • og:video / JSON-LD：正规站点的结构化元数据
  • 流直链：m3u8 / mpd / mp4 直接粘进来，会自动展开清晰度供选

拿不到的四类，以及为什么

类型为什么拿不到还能怎么办
DRM（Widevine / FairPlay） 分片是密文，密钥在版权方；浏览器播放本身也要许可证 没有可行办法。腾讯/爱奇艺会员正片、Netflix 都在这里
播放地址二次加密（encrypt=1） 地址由站点自己的 JS 解出，规则随版本变 用浏览器插件在播放时嗅探（IDM 也是这么干的）
blob: + MSE 真实地址只存在内存里，HTML 里没有 装插件，在网络层截真实请求
付费 / 会员清晰度 不绕付费墙 带你自己的 Cookie，能拿到你能看的档位

为什么要带 Cookie

很多站点游客只给 480P，登录后才有 1080P；还有些 CDN 直接校验 Cookie。 两种给法：设置 → 网络 → Cookie → 从浏览器读取； 或者装插件，右键「用汲流下载此链接」时它会把当前会话的 Cookie 一起带过来。

应用没开着，点链接也能唤起（1.9.4）

不需要先打开汲流。网页上点一下、或者浏览器扩展拦到下载，它会自己起来。

怎么生效

第一次启动时，汲流会在注册表里登记一个 jiliu:// 协议（只写当前用户， 不弹管理员权限框）。之后这两种情况都会自动唤起：

  • 浏览器扩展：拦截到下载 → 发现本机服务连不上 → 用 jiliu://wake 把应用拉起来 → 等它就绪 → 把完整任务（含 Cookie/Referer）补发过去
  • 网页里的链接：任何 <a href="jiliu://download?url=..."> 点下去都会交给汲流

为什么目录里多了个 jiliu-wake.exe

注册表指向的是它，不是主程序。主程序是 25MB 的单文件包，Windows 每次启动 它都要把内容解包一遍 —— 拿主程序当协议处理器，点一次链接要等六秒多。 jiliu-wake.exe 只做三件事：读一下运行中的端口、把任务发过去、退出。 10MB，实测 2.5 秒左右。

少了它也能用：汲流会退回指向主程序，功能完全一样，只是慢。 所以这两个文件请放在同一个目录里。

三种写法

写法用途
jiliu://download?url=<编码后的链接> 唤起并直接建任务。可加 &referer=、&title=、&kind=video
jiliu://wake 只唤起，不建任务。扩展用它叫醒应用，之后自己走本地 API 补投
jiliu:https://example.com/a.zip 冒号后直接跟原链接，最省事

链接里的 ? 和 & 必须 percent 编码，否则会被协议串自己的 query 解析吃掉后半段 —— 表现为"签名地址被截断，下载 403"。用设置页里的「试试看」 可以验证一条链接能不能被正确解析。

为什么扩展不直接把 Cookie 塞进协议串

协议串会被浏览器记进历史，也会落进系统的 URL 处理日志。把登录态写进去， 等于把 Cookie 摊在磁盘上。所以协议串只承担「叫醒」，真正的请求仍然走 127.0.0.1 的本地 API —— 那条路上敏感信息一个字节都不出内存。

设置在哪

设置 → 自动化 → 协议唤起（jiliu://）。这里能看到当前注册状态、 指向的可执行文件路径、最近五次唤起的成功或失败原因，也能手动注册/取消。

常见情况

现象原因与处理
浏览器弹「是否打开汲流」 正常。勾选「记住我的选择」之后不再问
点了没反应 先看设置页的「最近一次唤起」。如果显示未注册，点「立即注册」； 如果是"不支持的链接类型"，说明协议串里带的是 javascript: 之类。 排查看 data/logs/wake.log，唤起器失败时会在那里留一行
点了链接，没有新窗口，但任务已经在列表里 正常。汲流本来就在后台跑着，唤起器把任务递给它之后就退了， 不会再开第二个窗口抢任务列表
唤起后窗口是空的，任务几秒后才出现 正常。冷启动要 3~5 秒（主程序解包 + WebView 初始化）， 任务在服务就绪后立刻入队
便携版换了目录后唤起失效 注册表里还指着旧路径。启动一次汲流会自动改正；也可以手动「立即注册」
公司电脑不让写注册表 协议唤起用不了，但扩展直连本地 API 仍然可用 —— 前提是先手动开着汲流
扩展点了悬浮按钮，还是弹「请先启动汲流」 扩展没重新加载。改过的代码要回 chrome://extensions 点卡片上的刷新才会生效。点扩展图标，顶栏应显示 v1.9.6 —— 看不到版本角标就说明跑的还是旧的
按钮不见了 / 跑到别处去了 按钮拖过之后会记住位置。想恢复默认：插件图标 →「页面组件」→ 「还原两个组件的位置」。另外它只在鼠标靠近视频时才出现， 离开 2 秒后自动隐藏，不是丢了
进度悬浮窗不出现 只在「顶层页面 + 有未完成任务 + 汲流在线」时出现。iframe 里不会重复挂； 刚下完会亮 5 秒「全部完成」再隐掉。也可以去插件弹窗看「页面组件」里 开关是不是关着
应用明明开着，扩展却显示「服务未启动」 旧版扩展只认 8788，而汲流在 8788 被占时会顺延到 8789、8790… 1.9.0 起的扩展会自动扫一段端口并记住新地址。同样需要重新加载扩展

安全边界

  • 协议参数是外部可控输入（任何网页都能构造），只接受 http / https / ftp / magnet / ed2k / thunder 等白名单协议，javascript:、 data: 一律拒绝
  • 只写 HKCU（当前用户），不碰 HKLM，不需要管理员权限
  • 卸载/取消注册会把整棵 Software\Classes\jiliu 删干净

浏览器插件

Chrome / Edge / 其他 Chromium 内核。MV3，要求 Chrome 111 以上。

加载

  1. 地址栏输入 chrome://extensions
  2. 右上角打开开发者模式
  3. 点加载已解压的扩展程序，选 extension 文件夹
  4. 点插件图标 → 检查 API 地址是 http://127.0.0.1:8788
几种失效情形
  • 知会权限没给 —— 插件要 downloads 权限才能接管下载。第一次装会被问，选「允许」。
  • 汲流没在跑 —— 插件会提示连不上。先双击汲流把面板开起来。
  • 端口改了 —— 面板里把 API 地址改成新端口，插件会自动跟着变。

四个功能

一、下载接管 —— 见下一节，这是主菜。

二、页面嗅探 —— 插件会钩页面里的 <video> / <audio> 标签，以及 fetch / XMLHttpRequest 请求， 把真实的媒体地址捞出来。点插件图标，列表里点「交给汲流」。

三、播放器外侧的下载按钮 —— 鼠标划过网页上的播放器，会浮出一个 「⬇ 下载视频」。它贴在视频框外面：优先放在视频上沿外侧（和 IDM 的位置一致）， 上面放不下就依次试右侧、下方、左侧；只有视频铺满整个屏幕时才退回内部， 并自动收成纯图标，尽量少挡播放器自己的按钮。

拖到顺手的位置

按钮可以直接拖动。松手后位置会记住，并且跟着视频框走（滚动、 窗口缩放都不会跑偏）。拖过之后就不再按默认规则自动摆位。

位置记录在本机 chrome.storage.local 里，不联网。 想恢复默认：点插件图标 →「页面组件」→「还原两个组件的位置」。

四、进度悬浮窗 —— 有任务在跑时，页面右下角出现一张小卡片， 每 4 秒自动切换一个视图：

视图显示什么
总速度所有进行中任务的合计速度 + 进行中/排队/暂停个数 + 总进度条
当前文件正在下的那个文件的百分比、文件名、速度、剩余时间
总进度这一批任务的合计百分比 + 已下 / 总量
交互
  • 拖标题栏换位置；点内容区手动切换视图（手动切过 8 秒内不自动转）
  • 鼠标停在卡片上时暂停自动轮转，方便盯着看
  • — 收成一窄条（只留速度），↗ 把汲流主窗口切到前台
  • 下完不会突然消失：先亮 5 秒「✓ 全部完成」，再自己隐掉
  • 任务全下完、或者汲流没开着时，卡片自动隐藏，不占地方

两个组件都能在插件弹窗的「页面组件」里单独关掉，改完立刻生效，不用刷新页面。

为什么嗅探要跑在页面主世界

MV3 的 content script 默认跑在隔离世界（isolated world）里。 隔离世界有独立的 JS 环境 —— 你在这里改写 window.fetch， 页面自己调用的那个 fetch 完全不受影响。

所以要加 "world": "MAIN"。inject.js 就是这么配的。 钩子在主世界捞到地址，再用 postMessage 传给隔离世界的 content.js —— 两个世界之间只有这一条通道。

下载接管

插件监听浏览器的每一次下载，先暂停、再判断、然后决定放行还是接管。

为什么必须先暂停

顺序错了就白费流量

chrome.downloads.onCreated 触发的时候， 下载已经在跑了。这时候你慢悠悠地发一个 HTTP 请求去问汲流 「这个要不要接管」，等你收到答复，几百 KB 可能已经下来了 —— 然后你 cancel() 掉，汲流从头再下一遍。流量白流，进度白费。

所以顺序是：先 pause()，再判断。 决定放行就 resume()，决定接管才 cancel()。

接管失败一定救回来

任何一步出异常（汲流没响应、网络抖、API 报错），都会走 chrome.downloads.resume() 把下载还给浏览器。

绝不允许出现「下载卡在暂停状态、无声无息」 —— 那比不装插件还糟。

三种模式

模式行为什么场合用
off 完全不管，浏览器自己下 调试插件、或临时不想被打扰
smart 默认 按下面的规则挑着接管 日常
all 所有 HTTP 下载全交给汲流 我就想要所有下载都走汲流

模式在插件弹窗里切换，改完立刻生效，不用重启浏览器。

smart 模式的判定链

判定逻辑实现在 jiliu/resource.py 的 intercept_decision()， 插件通过 POST /api/intercept 调用它。也就是说 —— 规则改在 Python 侧， 插件不用重新加载。

接管之后

汲流收到请求，再走一遍完整识别（这次是联网探测 + 读文件头， 比插件那点信息准得多），然后按类型选引擎、定线程数、决定要不要校验哈希，建任务开下。

插件侧和主程序侧的判定是两套

插件那层是粗筛 —— 它只有 URL、MIME 和文件名，还没碰过文件本身。 主程序那层是精判 —— 能发 Range 请求读前 1KB 文件头。

所以可能出现：插件觉得该接管，汲流一看文件头发现是张 200KB 的图， 于是老老实实单线程下完了。这不算打架，这是分层。

类型识别

jiliu/resource.py —— 10 个分类、237 个后缀、64 条魔数签名。这是「下载接管」的脑子。

四路嗅探

一个文件是什么，可以从四个地方看出来。四条线索按可靠度加权，投票定胜负。

魔数的二级分类

文件头能分出大类，但同一个头下面还有细分 —— 这层最容易写漏。

ZIP 家族（PK\x03\x04）

光看头部，.docx / .xlsx / .pptx / .apk / .jar / .msix / .epub 全都长一样。要解开内部条目名才能判断。

坑：必须扫全部条目，不能只看第一个

早期写法只读第一个 local file header。结果 MSIX 识别不出来 —— 因为它的 [Content_Types].xml 通常排在第二个， 第一个是别的东西。

改成循环扫全部条目名（上限 24 个），MSIX 就认出来了。

RIFF 家族（RIFF????）

要看偏移 8–12 字节：

  • AVI → 视频
  • WAVE → 音频
  • WEBP → 图片

MP4 家族（????ftyp）

要看 brand：

  • isom / mp42 → 视频
  • M4A → 音频
  • avif / heic → 图片

两个反直觉的设计

平台识别不压过后缀

x.com/sprite.png 命中了 X/Twitter 平台域名。 但它有明确的 .png 后缀，就是个静态图片 —— 不该硬塞给 yt-dlp 去「解析」。

所以有明确文件后缀且属于静态类型时，按直链处理。

占位后缀让位给魔数

CDN 经常把 PDF 存成 file.bin。 如果后缀优先，就会当成「未知二进制」处理。

所以 bin / dat / download 这类 占位后缀被标记为 generic，魔数一旦有结论就直接改判。

分类一览

视频video 音频audio 应用app 压缩包archive 文档document 光盘镜像disk 图片image 字体font 数据集/模型dataset 其他文件other

每类东西该怎么下，是这张表说了算。

分类 引擎 线程 分片 校验哈希 可解压 说明

三个刻意的设计
  • 应用 / 压缩包 / 镜像 / 数据集强制校验哈希 —— 这四类下坏了代价最大。装到一半报错的安装包、解压到 99% 失败的压缩包， 比压根没下更烦人。
  • 小文件降级单线程 —— 每个分类都有 min_multithread 门槛。40 KB 的文件开 8 个连接， 握手开销比传输本身还大。
  • 文档并发降到 6、分片降到 512 KiB —— 文档普遍不大，太多连接是纯浪费。

表里的 KiB / MiB 是 1024 进制。面板和命令行显示成 1.00 MB 也是按 1024 算的（跟 Windows 的习惯一致），不是 1000。

统一下载协议

从各处复制来的「链接」并不都是 http:// 开头。 汲流在识别类型之前先过一层协议判定，按链接的真实形态分流给不同引擎。

链接形态 处理方式 走向
magnet:?xt=urn:btih:… 取 info hash、还原显示名 aria2 的 BT 引擎
*.torrent 下种子后交给 BT 引擎 aria2 的 BT 引擎
ed2k://|file|… eDonkey 链接 aria2 的 BT 引擎
thunder://… base64 解壳，去掉 AA…ZZ 解出内层 URL 后照常识别
qqdl://… base64 解壳 解出内层 URL 后照常识别
flashget://… base64 解壳，再去 [FLASHGET] 标记 解出内层 URL 后照常识别
网盘分享页 只识别 + 如实说明 native 单线程
迅雷链接长什么样 
thunder://QUFodHRwOi8vY2RuLmV4YW1wbGUuY29tL3NldHVwLmV4ZVpa
            └─ base64 解出来是 → AAhttp://cdn.example.com/setup.exeZZ
                                 └─ 去掉 AA / ZZ → 真正的下载地址

解壳之后的地址就是普通 HTTP 直链，交给多线程引擎跑满带宽。 壳里裹的也可能是个种子，所以解完还要重新走一遍完整识别。

BT 为什么不自己写

磁力 / 种子 / ed2k 一律交给 aria2，自研引擎不碰 P2P。 DHT 找源、PEX 交换、LPD 本地发现、peer 阻塞检测、分块优先级调度 —— 这是一个独立且庞大的领域，重写一遍的收益远小于直接复用 aria2。

代价是下 BT 需要 aria2c。没装时汲流会直接说 「BT 需要 aria2 后端」，不会假装在下然后卡在 0%。

网盘：说清楚能做什么、不能做什么

不做：逆向百度网盘 / 夸克 / 115 的私有接口来「提速」。 那既违反服务条款，维护成本也高得离谱 —— 接口一改就废，属于典型的负资产。

做：识别出是哪个网盘，然后告诉你怎么拿到直链。 拿到直链后，普通多线程引擎本来就能满速下。已识别的网盘：

百度网盘、阿里云盘、夸克网盘、天翼云盘、115 网盘、123 云盘、蓝奏云、 Google Drive、MEGA。（未列出的域名按普通链接处理，不做猜测。）

命令行随时可以查一个链接的协议判定：

python jiliu.py protocol "magnet:?xt=urn:btih:..."
python jiliu.py protocol "thunder://QUFodHRwOi8v..."
python jiliu.py protocol "https://pan.baidu.com/s/1abc" --json

合集下载

B站合集、YouTube 播放列表与频道，都按「合集」处理。 这是单集下载之外最常用的一件事。

三个默认行为，都有理由
  • 建子目录 + 文件名带序号前缀（%pl_index% - ）—— 不这么做，下完是一堆名字相似的文件混在一起，按标题排序就是乱的。
  • 可以先探测、只挑其中几集下 —— 面板里是个勾选列表， 命令行用 --items 3,5,7。整季重下没人受得了。
  • 跳过已下载 —— 补集时不用人工比对，同一集不会重复下。

B站合集优先走官方接口（更快、标题更准）， 失败才回退到 yt-dlp 通用解析。

# 只下第 3、5、7 集
python jiliu.py video "https://space.bilibili.com/xxx" --playlist --items 3,5,7

# 只抽音轨（需 ffmpeg）
python jiliu.py video "<url>" --playlist -x

B站登录与 Cookie

B站高清（1080P+）与部分合集需要登录态。两种拿凭据的方式：

# 方式一：扫码登录（推荐）
python jiliu.py bili login       # 面板菜单里也有「B站登录」按钮

# 方式二：从浏览器导出 cookies.txt 后导入
python jiliu.py cookies import cookies.txt --label bilibili.com
python jiliu.py cookies browsers  # 看本机哪些浏览器能被读

⚠️ Chrome / Edge 127+ 读不了（App-Bound 加密，纯 Python 解不开， yt-dlp 也一样）。Firefox 不受影响。

双击 exe 等于 serve

打好的 jiliu.exe 不带参数双击时，会自动执行 serve 并打开浏览器 —— 双击就该是「能用」，而不是弹一屏帮助。

外部工具

汲流本身不捆绑 ffmpeg。有则用，没有则降级，不会假装能用。

工具用途必需性
yt-dlp 视频站解析与下载 打包版已内置；便携版可放 bin/yt-dlp.exe 覆盖成更新的
ffmpeg 音视频合并、抽音轨 下「音视频分离」的站点（B站、YouTube 高清）必需
ffprobe 媒体信息探测 可选
aria2c 备用下载引擎 可选。也可当 Motrix 的 RPC 后端用

放哪儿？便携版放程序目录的 bin/； 安装版放 exe 同级的 bin/ 或 tools/。 汲流会自动认出来。

yt-dlp 的版本择优

不看形式，看版本号

机器上可能同时存在三份 yt-dlp：scoop 装的 exe、pip 装的 module、 exe 里内置的那份。汲流会把三份都拿出来比版本号，选最新的用。

为什么在意这个：站点改版太频繁，差两年的老版本会大面积解析失败。 版本旧不是「功能少一点」，是「根本用不了」。

常见问题

为什么 exe 有 17 MB？

因为把整个 yt-dlp 包进去了。yt-dlp 靠 importlib 动态加载 extractor —— 几千个站点的解析器分散在几百个模块里， 只做静态分析会漏掉一大半（冻结态实测枚举出 1752 个 extractor）。 必须 --collect-submodules yt_dlp 整包收集。

换来的是：目标机器不装 Python 也能用。如果更在意体积， 可以改成不内置、只走 bin/yt-dlp.exe 外部依赖 —— 代价是视频功能 得自己准备一份 yt-dlp。

磁力 / 种子下不动？

BT 需要 aria2c。汲流不自研 P2P（DHT 找源、PEX、peer 调度是 一个独立领域，重写一遍收益远小于复用 aria2），磁力 / .torrent / ed2k 一律交给 aria2 的 BT 引擎。

没装 aria2c 时任务会明确报「BT 需要 aria2 后端」，不会假装在下。 放一个 aria2c.exe 进 bin/ 即可 —— 面板左下角状态栏和「环境体检」都能看到它有没有被认出来。

网盘链接为什么不能直接下？

因为汲流不逆向网盘的私有接口（百度 / 夸克 / 115 这类）。 那既违反服务条款，维护成本也高得离谱 —— 接口一改就废。

汲流能做的是：认出这是哪个网盘，然后告诉你怎么拿到直链。 拿到直链之后，普通多线程引擎本来就能满速下。已识别的网盘见 统一下载协议。

YouTube 报「Sign in to confirm you're not a bot」

这是 YouTube 的风控，不是解析器坏了。两个条件缺一不可：

  • 本机代理 —— 国内直连本来就到不了 YouTube
  • 登录态 Cookie —— 用插件导出 cookies.txt， 然后 jiliu.exe cookies import cookies.txt --label youtube.com

⚠️ Chrome / Edge 127+ 的 Cookie 直接读不了：它们给 cookie 库 加了 App-Bound 加密，纯 Python 解不开（yt-dlp --cookies-from-browser 同样不行）。Firefox 不受影响；否则就用扩展导出 cookies.txt 再导入。

迅雷 / 旋风 / 快车的链接能用吗？

能。这三种「专属链接」本质上是普通 URL 套了一层 base64 壳， 解开就是普通下载地址。汲流在识别类型之前会先解壳，解完的地址照常多线程下载。

注意壳里裹的也可能是种子 —— 所以解壳不是终点， 解完还要再走一遍完整识别。

下载速度没变快？

先跑 jiliu.py probe <url> 看服务端支不支持 Range。 不支持就只能单线程 —— 有些 CDN 和网盘故意这么干， 这不是汲流的问题，也没法绕。

另外确认文件不小于 min_multipart（默认 1 MiB）。 小文件是故意降级单线程的。

视频下下来没有声音？

B站、YouTube 的高清是音视频分离的（视频一路、音频一路）， 需要 ffmpeg 合并。装个 ffmpeg 放进 bin/ 就好。

临时应急可以用 -f 选一个有声音的单文件格式：

python jiliu.py video <url> -f "b[ext=mp4]"   # 单文件，画质通常 720p 以内

被接管了想拿回来？

插件弹窗里把模式改成 off，立刻生效，不用重启浏览器。

只想让某几个站别被接管？填进 skipHosts，每行一个域名。

DRM 的内容下不了

是设计如此。video.probe() 会检测 DRM 并明确报出来， 而不是让你等一个注定失败的任务。本工具不提供也不打算提供 DRM 破解能力。

分片下载中断了怎么办

直接用相同命令再跑一次就行 —— 已完成的区间会跳过。 任务记录里也会保留断点信息。

怎么彻底清干净？

  • 安装版：控制面板卸载，或跑 jiliu-setup.exe --uninstall。 之后手动删 ~/.jiliu/（配置与任务记录）。
  • 便携版：整个文件夹删掉即可，不残留任何东西。
